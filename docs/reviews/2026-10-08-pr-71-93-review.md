### F1 · P2 · PR 84 — Regenerated movers break the browser gate

**Location:** [new tables in changes/page.tsx:63](/Users/ericwyluda/Development/macrogauge/site/src/app/changes/page.tsx:63), interacting with [batch4.spec.ts:57](/Users/ericwyluda/Development/macrogauge/site/e2e/batch4.spec.ts:57).

The new movers and unchanged tables are inserted before the existing headline/component tables. The older test still selects `table.data-table.nth(1)` and requires 14 component rows. With committed `changes.json`, `movers` is absent, so the new tables are absent and CI passes. Regenerating the artifacts through the current writers activates them: the test then inspects the unchanged table and fails **Expected 14, Received 30**. The full suite produced **232 passed, 1 failed** with valid build metadata. The final fixture run's result is recorded in the evidence file.

This is a deterministic integration failure awaiting the new publish, not a chart failure. `.github/workflows/ci.yml` runs the browser suite after the daily workflow completes, so subsequent published data can turn the site CI job red even though the PR checks were green. Vercel deployment is separate; this review did not establish an outage or deployment block.

**Correction/test:** select the intended component table by a stable identifier or section, and run the full browser suite against a representative artifact containing nonempty `movers`, including changed, unchanged, and new readings. Keep the old-artifact compatibility check too.

### F2 · P2 · PR 92 / 90 — Hardware comparison links discard their subject

**Location:** [component page:135](/Users/ericwyluda/Development/macrogauge/site/src/app/datacenter/components/[code]/page.tsx:135), [calculator roster:24](/Users/ericwyluda/Development/macrogauge/site/src/app/calculator/page.tsx:24), [selection filtering:29](/Users/ericwyluda/Development/macrogauge/site/src/components/EscalationSinceClient.tsx:29).

All five hardware component pages offer a link such as `/calculator?series=storage,dc_hardware`. However, the calculator offers composites plus `clause_series`; the latter publishes build/ops/reference series and excludes hardware components. The client silently filters unknown keys. Following the storage page's link in the browser therefore checks only **DC Hardware index** and shows one row/line. Storage is neither selected nor offered. `hw_imported`, `semis_components`, `imported_semis`, `storage`, and `network` all fail this way.

The link explicitly promises to compare the component with other indexes; readers instead receive the composite alone, without an explanation. [Browser screenshot](/Users/ericwyluda/Development/macrogauge/docs/reviews/2026-10-08-pr-71-93-hardware-link.png).

**Correction/test:** supply compatible monthly hardware series to the calculator, or change/remove the unsupported component comparison action. A route-level test should follow each component link and assert both requested series survive into the table and chart.

### F3 · P2 · PR 71 — One headline combines incompatible BBB change windows

**Location:** [ratesHeadline.ts:33](/Users/ericwyluda/Development/macrogauge/site/src/lib/ratesHeadline.ts:33).

The title uses `bbbYield.chg_1y` for the change, then appends a causal attribution calculated from `move.yield_chg_1y` and `move.oas_chg_1y`. The latter intentionally end at the shared yield/OAS date, which may lag the yield series. These are not necessarily the same annual window. Before this rewrite the dated shared-window explanation was separate; the new title directly attaches its attribution to the latest change.

A controlled lag fixture yields **“up 119bp on the year, mostly from the credit spread”**, while the dated detail says the spread **fell 100bp** and the corresponding yield **fell 110bp**. The publisher's shared-window protection is defeated by the presentation. Current equal-date inputs need not show the defect.

**Correction/test:** derive the attributed move from the same shared window and name its date, or leave the attribution in the separate dated statement. Cover differing dates, opposite directions, and missing latest-year changes.

### F4 · P2 · PR 93 — Scoreboard's “last N prints” ranking is not head-to-head

**Location:** [scoreboardHeadline.ts:9](/Users/ericwyluda/Development/macrogauge/site/src/lib/scoreboardHeadline.ts:9); producer behavior at [phase3.py:326](/Users/ericwyluda/Development/macrogauge/pipeline/publish/phase3.py:326).

The helper sorts each forecaster's independently calculated MAE, takes the smallest sample count, and describes all of those MAEs as performance over the last `N` prints. Missing predictions are supported: the producer calculates each statistic from whichever rows that forecaster has, without intersecting months.

Repro: MacroGauge errors are `[0, 1]`, giving MAE `0.500` over two prints; Cleveland has only the second print, error `0.600`. The headline calls MacroGauge the smallest miss “over the last 1 graded print.” On that shared print Cleveland actually wins, `0.600` versus `1.000`. The small-sample disclaimer does not fix the incorrectly specified window or ranking. The committed three-print record has equal counts; this is a conditional missing-data defect.

**Correction/test:** calculate a common-period comparison from `rows`, or explicitly report separate sample counts without asserting a common-window leader. Test unequal counts and equal counts with different missing months.

### F5 · P2 · PR 81 — Place disambiguation truncates multiword locations

**Location:** [newsTape.ts:221](/Users/ericwyluda/Development/macrogauge/site/src/lib/newsTape.ts:221).

The new place extractor captures only the first capitalized word after `in`, `at`, `near`, or `outside`. Therefore “Microsoft opens a 500 MW data center in **New York**” and the same wording in **New Jersey** both become the place `new`. `sameStory` returns true and `clusterStories` produces one story. The same problem applies to shared-prefix locations such as North Carolina/North Dakota or San Jose/San Antonio. One distinct project becomes a secondary item behind another story.

This is a residual failure in PR 81's attempted location fix, rather than a newly introduced behavior: its single-word Texas/Finland case works. The report does not treat every fuzzy news-clustering decision as a defect; this probe names two unambiguously different places with otherwise identical facts.

**Correction/test:** retain complete place names for the veto, while preserving the same-place rewrite control. Include New York/New Jersey, North Carolina/North Dakota, and a same-location longer headline.

### F6 · P2 · PR 84 — Percentage changes reverse direction from a negative power-price base

**Location:** [changes.py:157](/Users/ericwyluda/Development/macrogauge/pipeline/publish/changes.py:157), consumed by [changesHeadline.ts:42](/Users/ericwyluda/Development/macrogauge/site/src/lib/changesHeadline.ts:42).

All levels use `(current / previous - 1) * 100`, including wholesale power averages, whose publisher/schema permit negative values. Moving from **−$10 to +$10/MWh** produces **−200%**, significance **66.67×**, and the headline **“Example hub fell 200.0% to $10.00/MWh.”** A rise is promoted as the largest decline. Even −$10 to −$5 reverses the ordinary direction of the change.

This is a valid-domain fixture; no negative current hub average is alleged. The older power YoY calculation already declines to compute percentages from a nonpositive denominator.

**Correction/test:** use an absolute $/MWh change and suitable threshold for nonpositive bases, or explicitly mark the percentage undefined. Test negative-to-negative, negative-to-positive, zero, and ordinary positive cases through both writer and headline.

### F7 · P2 · PR 83 — Nonpositive power averages produce `NaN` map coordinates

**Location:** [HubMap.tsx:35](/Users/ericwyluda/Development/macrogauge/site/src/components/HubMap.tsx:35).

Circle radius is `6 + 12 * sqrt(avg30 / max)`. With one $20 hub and one −$5 hub, the latter renders `r="NaN"`; its label position also becomes `NaN`. When the only shown averages are zero, division is `0/0`. React reports invalid radius/coordinate attributes. The table can still show those prices, but the map loses the corresponding visual marker and label.

**Correction/test:** define a finite scale for the full allowed price domain, preserving a readable minimum marker and explicit signed prices. Render mixed-sign and all-zero fixtures and assert every radius/coordinate is finite. This is separate from F6: it has a different consumer and correction.

### F8 · P2 · PR 91 — Outlook calls every qualifying hump a base effect

**Location:** [outlookHeadline.ts:46](/Users/ericwyluda/Development/macrogauge/site/src/lib/outlookHeadline.ts:46).

Once the forecast forms a hump and three year-ago levels are present, the function unconditionally writes “Much of the hump is base effect.” It never measures whether denominator movement explains the hump or whether the forecast numerator drives it. With year-ago levels all `100` and forecast YoY `2% → 3% → 2%`, the note still makes that assertion while reporting that both historical legs rose `0.0%`. In this fixture the denominator is constant and explains none of the hump.

**Correction/test:** describe the historical comparison neutrally, or quantify a denominator-only counterfactual before attributing most of the move to it. Cover flat, opposite-direction, small, and dominant base effects. This finding concerns the general generator, not a claim that today's specific hump has no base effect.

### F9 · P2 · PR 93 — A cost-of-living jump is automatically labeled rate-driven

**Location:** [cost-of-living/page.tsx:100](/Users/ericwyluda/Development/macrogauge/site/src/app/cost-of-living/page.tsx:100), condition at [colJump.ts:19](/Users/ericwyluda/Development/macrogauge/site/src/lib/colJump.ts:19).

`colJump` tests only whether cost-of-living YoY increased at least 1.5pp in 60 days; mortgage rates and the gauge do not affect the trigger. The page nevertheless labels the marker “rate-driven jump.” A fixture with both COL and the gauge rising `3% → 5%`, and mortgage rates unchanged at `6%`, receives the same annotation. Broad inflation or home-price moves can thus be mislabeled as a rate effect.

**Correction/test:** use “cost-of-living jump” unless a rate contribution is actually computed. Checking a rate increase alone would still not establish how much of the jump it caused. Test a flat-rate jump, falling rates, and a measured mortgage-payment contribution.

### F10 · P3 · PR 90 — Latest-month input is incorrectly called missing data

**Location:** [escalationSince.ts:40](/Users/ericwyluda/Development/macrogauge/site/src/lib/escalationSince.ts:40), [empty-row message:108](/Users/ericwyluda/Development/macrogauge/site/src/components/EscalationSinceClient.tsx:108).

`i >= last` returns null even when the requested base is the existing last month. The browser with Hardware and `since=2026-10` says **“No level for 2026-10: this series runs 2017-01 to 2026-10.”** The adjacent `rebased` helper correctly finds the level and returns `[100]`.

**Correction/test:** return zero elapsed change, unchanged amount, and no annualized rate for an available latest-month base, or explicitly say “no elapsed interval.” Reserve the missing-level explanation for an actual gap. Test the exact final month and the month after it separately.

### F11 · P3 · PR 90 — Amount validation differs between typing and sharing

**Location:** [EscalationSinceClient.tsx:60](/Users/ericwyluda/Development/macrogauge/site/src/components/EscalationSinceClient.tsx:60), URL bounds at line 27.

Typing writes `Number(input)` directly into state; `min=1` does not stop computation and there is no form validation gate. URL loading instead rejects values outside `[1, 1e12]`. In the browser, typing `-100` produced **−$100 becomes −$133** and wrote `amount=-100`. Reloading that same URL produced **$1,000,000 becomes $1,331,958**, silently falling back to the default. Clearing the field similarly converts it to zero.

**Correction/test:** use one validator for local inputs and URL state, retain an explicit invalid/empty state, and avoid displaying an escalated result until the amount is valid. Test blank, zero, negative, oversized, and valid values through a reload round trip.

### F12 · P3 · PR 91 — Weighted ensembles are mislabeled equal-weight

**Location:** [ForecasterDots.tsx:50](/Users/ericwyluda/Development/macrogauge/site/src/components/ForecasterDots.tsx:50).

The legend is hardcoded to “equal-weight ensemble.” The producer supports inverse-MAE weights once each forecaster has six graded prints, and the preview passes only the resulting value to this component. A supported producer fixture with forecasts `0.10` and `0.40`, weighted `0.8/0.2`, returns `0.16`; the rendered legend still says equal-weight, which would imply `0.25`. The current short record is equal-weight, so this manifests when the existing earned-weight mode activates.

**Correction/test:** pass the actual weight mode or use the neutral label “ensemble.” Render both equal and earned weights, including a case where their values differ materially.

### F13 · P3 · PR 93 — Gap chart's vertical axis has the wrong unit

**Location:** [MyInflationClient.tsx:259](/Users/ericwyluda/Development/macrogauge/site/src/components/MyInflationClient.tsx:259), inherited [chartTheme.ts:51](/Users/ericwyluda/Development/macrogauge/site/src/lib/chartTheme.ts:51).

The new chart plots personal YoY minus gauge YoY, and its title, tooltip, and neutral band correctly use percentage points. But it inherits `yAxis.axisLabel.formatter = "{value}%"` from `baseOption()` without overriding it. Its axis labels therefore express the difference as a percentage instead of percentage points.

**Correction/test:** label that axis in `pp`, and check the rendered option/labels alongside tooltip and band units. The underlying gap calculation is not alleged to be wrong.
