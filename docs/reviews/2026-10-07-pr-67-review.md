## F1 — P2: Describe industrial electricity as a state-average proxy, not a large-load tariff

**Location:** `site/src/app/states/page.tsx:40–43`; the same interpretation appears in `site/src/lib/siteCosts.ts:7`.

The new lede tells readers these are the industrial power prices a large load pays, as part of what it costs to build and run a data center. The underlying data are still the EIA state industrial-sector average-price series (`ELEC.PRICE.CA-IND.M`, `ELEC.PRICE.NM-IND.M`, etc.). Nothing in this PR adds a utility, rate schedule, service voltage, load profile, or data-center contract to those observations.

EIA explicitly defines the measure as sector revenue divided by electricity sales and explains that the resulting weighted average does **not** equal the rate charged to an individual customer; utilities use multiple schedules within a sector. See [Electric Power Monthly, Appendix C, page 7](https://www.eia.gov/electricity/monthly/pdf/AppendixC.pdf#page=7).

**Impact:** the new site-selection framing turns a useful geographic comparison into an unsupported claim about a prospective project's actual electricity cost. For example, the California/New Mexico 6.0× spread is a spread between state industrial averages, not an established 6.0× spread between otherwise comparable data-center power contracts. The existing source footnote does not disclose this distinction.

**Correction:** retain the industrial default, but explicitly call it an EIA state industrial-average screening proxy. Explain that a project's applicable utility tariff and contract determine its actual bill, and link the existing `/power` tariff information where helpful. Apply the same terminology to the headline and metadata as appropriate.

## F2 — P2: Qualify the headline when the comparison has missing or mixed-month observations

**Location:** `site/src/lib/siteCosts.ts:48–54`.

The new headline drops null prices, requires only two remaining observations, ignores their `as_of` dates, and then unconditionally claims a spread across the 48 contiguous states. The publisher deliberately supports null measures and selects each electricity series' own latest observation (`pipeline/publish/geo.py::_measure`); unlike construction wages, electricity is not pinned to a shared period. A partial collection can therefore leave different states on different months.

**Offline reproductions using copies of the committed artifact:**

1. Set only California's industrial measure to `{value: null, as_of: null, yoy_pct: null}`. The artifact remains schema-valid and has 47 priced contiguous states. The helper nevertheless returns: “Across the 48 contiguous states, industrial power costs 5.5× as much in Rhode Island (22.9¢/kWh) as in New Mexico (4.2¢)…” The unavailable highest-price state has silently changed the claimed comparison.
2. Restore the artifact and change only California's industrial `as_of` to `2026-06-01`, leaving New Mexico and the US on `2026-07-01`. The artifact remains schema-valid. The complete headline is byte-for-byte unchanged and contains no indication that its extrema refer to different months. The US KPI's July date cannot date those state observations.

The map's existing general note about each state's latest reading does not identify the headline's coverage or the dates of its endpoints. The new unit test also expects “48 contiguous states” from a fixture containing only three priced contiguous states, so it enshrines the coverage error.

**Correction:** establish the headline's reporting cohort and reference period. Either require complete comparable coverage for the unqualified 48-state claim, or name the number of reporting states and disclose the differing endpoint periods. Add missing-extreme and mixed-month cases whose expectations preserve those qualifications.

This is a reproduced supported-data failure mode, not a claim that the committed snapshot is incomplete: all 51 industrial observations in that snapshot are present and dated July 2026.

## F3 — P2: Meet the small-text contrast threshold throughout the new map ramp

**Location:** `site/src/components/GeoStateMap.tsx:112–115`; palette: `site/src/lib/heat.ts:30–43`; insufficient sampling: `site/src/lib/heat.test.ts:39–42`.

Switching the map to `levelRamp` introduces backgrounds on which neither the existing dark ink nor white achieves 4.5:1. `textOn()` only chooses the better of those two options; it cannot guarantee the threshold. The state abbreviations and values are 11px and 10px, so the large-text exception does not apply. See [WCAG 2.2 contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

**Reproduction on the committed data:** the default industrial map spans 4.16–39.33¢/kWh. California's 25.11¢ gives `t = 0.59568`, background `rgb(82,132,205)`, and ink `#17212B`: **4.2990:1**. Alaska's 24.81¢ gives **4.3558:1**. Both passed with the previous ramp at the same normalized values: **4.8131:1** and **4.7116:1**, respectively. Browser inspection of the built page confirmed California's actual computed colors and 11px/10px font sizes; an independent Python sRGB calculation confirmed the ratios.

Sweeping the actual state values finds **17 failing state/metric combinations**:

| Metric | States below 4.5:1 |
| --- | --- |
| Industrial power | AK, CA |
| Construction wage | AZ, GA, NV, OH, VA |
| Residential power | CA |
| Gas | NV |
| Unemployment | AK, LA, MA, MN, NJ, NY, OK, TX |

The lowest current combination is approximately **4.0370:1**. The added test checks only `t = 0, 0.25, 0.5, 0.75, 1`, missing the failing interval between the middle two samples.

**Correction:** adjust this ramp's text-color policy or palette so the selected ink passes throughout the interpolation (a sufficiently dark alternative to `#17212B` can close the gap). Verify a dense ramp sweep plus real state values, rather than only the five stops. Keep any change to shared `textOn()` covered for existing consumers.

## F4 — P3: Measure QCEW publication lag from the end of the quarter

**Location:** `site/src/app/states/page.tsx:62`.

The new wage KPI says QCEW publishes about seven months after the quarter. For the displayed Q1 2026 observation, BLS lists publication on **August 28, 2026**, 150 days (about five months) after March 31. The current [BLS QCEW release calendar](https://www.bls.gov/cew/release-calendar.htm) supplies that date, and the [program overview](https://www.bls.gov/cew/overview.htm) describes publication within six months of quarter-end. The connector's own documentation also says approximately five months.

**Impact:** the explanation introduced to clarify stale-looking wages overstates the normal release delay. The artifact's `2026-01-01` is a quarter-start label; elapsed time from that label is not the publication lag after Q1 ended. This affects the freshness explanation, not the wage value or Q1 label.

**Correction:** say approximately five to six months after quarter-end, or use the dated release schedule. Keep the observation period, the source's publication date, and the age of the observation distinct.
