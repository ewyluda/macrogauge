## F1 — P2: Disclose when a market's trend covers fewer counties than its headline

**Location:** `site/src/components/markets/MarketsClient.tsx:267–271`; producer: `pipeline/publish/dc_markets.py:123–130`.

The new sparkline appears immediately below `emp_cur_total` and its accessible label calls it the market's construction-worker history. However, the total includes all counties reporting this quarter, while `_history()` keeps only counties reporting throughout the entire window. The publisher supplies `history.counties`, but the component never renders it. The existing partial-coverage dagger checks the current/YoY county set, so it does not identify a county omitted solely because of an intervening historical quarter. Expanded receipts also describe the current/YoY sets, not the history set.

**Independent offline reproduction:** built an eight-quarter, two-county fixture with the real publisher. County A rises from 100 to 170 workers; county B falls from 1,000 to 300 and is absent only in Q4 2024. Both report in Q1 2025 and Q1 2026, so the latest YoY basis includes both. The schema-valid output has:

- `emp_cur_total = 470`, `emp_yoy_pct = -43.4`.
- `counties_used = counties_total = 2`, `counties_suppressed = []`.
- `history.counties = 1`, `history.emp = [100,110,120,130,140,150,160,170]`.

Rendering the actual `MarketsClient` produces **470** followed by an upward sparkline whose accessible description ends at **170**, with no dagger or history-coverage label. The method note explains the general constant-county rule, but readers cannot identify which rows have this mismatch or which counties the line represents. This can present a small county's expansion as the trajectory of a shrinking market.

**Correction:** retain the constant county set, but label partial history beside the sparkline and in its accessible description (for example, “1 of 2 counties”). Publish the included/excluded county identities if the expanded receipts are intended to reconcile the history. Distinguish its last value from the full-market headline.

This is a reproduced supported-data case, not an assertion that today's 19 populated market histories have partial coverage: all 19 currently include their full county sets.

## F2 — P2: Override the rate-based color when plotting headcount levels

**Location:** `site/src/components/markets/MarketsClient.tsx:269–270`; default behavior: `site/src/components/TailSpark.tsx:41` and `site/src/lib/format.ts::yoyColor`.

The new call passes absolute headcounts without a `stroke`. `TailSpark` defaults to `yoyColor(last)`, which chooses the inflation-hot red color for any value above 0.05. Consequently every populated market gets a red sparkline regardless of whether employment is increasing, flat, or falling. This conflicts with the page's red/emerald hot/slack semantics and does not encode the movement being plotted.

**Independent offline reproduction:** regenerated the publisher output from the saved store without fetching any data, validated it against the PR schema, and server-rendered the actual component. All **19** sparklines use `var(--accent-red)`, including **seven** declining histories. Examples for Q2 2024–Q1 2026:

| Market | First workers | Latest workers | Rendered stroke |
| --- | ---: | ---: | --- |
| Chicago | 109,676 | 101,266 | Red |
| Phoenix | 179,972 | 177,067 | Red |
| Quincy | 1,800 | 1,572 | Red |

**Correction:** pass an explicit neutral stroke for headcount levels, or deliberately select color from a defined change/tightness measure and describe that meaning. Do not feed a positive level into a helper intended for signed rates.
