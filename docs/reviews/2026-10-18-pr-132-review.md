## Findings, in severity order

### 1. P2 — Use the series cadence instead of the last observation gap to close steps

**Location:** `site/src/lib/chartPairs.ts:26–30` (especially `const next = b + (b - a)`).

`closeStep` infers the next period from the distance between the final two dates. This is not a reliable cadence when a monthly series skips a print. The repository's actual `compare.json` omits October 2025: its September observation is followed by November. Truncating that committed history at November and passing it through the actual `HeroChart`, `ColChart`, and `LinesChart` components appends **December 31, 2025 at 2.74%**, although the intended monthly closure is **November 30**. The PR therefore invents another 31 days of flat official CPI coverage, beyond the reference month supported by the last print. The same calculation can overextend a quarterly series after a missing quarter.

This is a conditional regression when the most recent observations contain a gap, not a claim that today's September 2026 chart tail is wrong. Today's consecutive August/September data closes correctly at September 30. The base components stop at the actual November 1 observation and do not create the false December endpoint. `pairWithBreaks` cannot prevent the problem for omitted months because the input contains no null placeholder; `LinesChart` additionally removes nulls before calling this helper.

**Correction:** pass an explicit monthly/quarterly cadence, or use a verified cadence with a conservative fallback when gaps make it ambiguous. Test monthly September→November and quarterly observations separated by a missing quarter, in addition to ordinary adjacent periods; keep daily/irregular series unextended.

**Evidence:** `2026-10-18-pr-132-evidence.json`, key `monthly_gap`. The reproduction evaluates the immutable head/base TypeScript modules and captures the options produced by all three actual chart components. React hooks and the rendering boundary are mocked; this evidence establishes the generated chart data, not a pixel-rendering claim.
