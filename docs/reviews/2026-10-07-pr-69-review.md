## F1 — P2: Resolve backfilled rows to their actual provenance instead of filtering by publish day

**Location:** `site/src/lib/ledgerSeries.ts:33–37`; the link is presented as verification at `site/src/components/AsOfClient.tsx:58–60`, and the new explanatory promise is at `site/src/app/as-of/page.tsx:61–62`.

`ledgerCommitsUrl()` always searches `store/ledger/pulse.jsonl` on the row's original publish day and the next day. However, this file was first added on September 3, with 74 rows, including 73 earlier publishes reconstructed from other artifacts. Their original publish timestamps are not the dates on which the ledger file recorded them. The new link therefore cannot find the promised append commit for most of the ledger, including the July–August DC revision history highlighted by the PR.

**Reproduction with committed data:** open `/as-of?date=2026-08-12&series=dc_hardware`. The selected row has `published_at = 2026-08-12T15:43:29Z`, DC Build `6.92%`, and DC Hardware `19.15%`. Its verification link searches:

```text
https://github.com/ewyluda/macrogauge/commits/main/store/ledger/pulse.jsonl?since=2026-08-12&until=2026-08-13
```

The row was actually appended by [commit 1471b1f](https://github.com/ewyluda/macrogauge/commit/1471b1f7b27e138e96a243691566345fef941d2b), committed September 3 at 20:31:59 UTC, outside that filter. Its original published artifacts are separately available at [commit 71a428c](https://github.com/ewyluda/macrogauge/commit/71a428c5bcc4064ad93023af5c73b7a72fa08388). A read-only GitHub API query for the ledger path over August 12 through the end of August 13 returned `[]`.

**Extent:** the offline reproduction resolves each row's actual first append from Git diffs. **At least 72 of 100 current rows** have append commits outside their generated date window, even generously treating the entire next day as included. These publishes span July 8 through September 1. There are 73 rows predating ledger creation; the September 2 boundary is excluded from the definite-failure count because its URL includes September 3. The latest October 7 row is a positive control: its append commit falls within its link's window.

**Impact:** the new “Verify: the commit that appended this row” control leads to empty history for historical readings that a reader is explicitly encouraged to cite in claims or change orders. The new unit test checks one recent URL's string, and the new browser test checks only the URL pattern, so both pass without establishing that the linked history contains the row's commit.

**Correction:** resolve a row's provenance from Git history when producing the site or a separate derived provenance artifact, then link to the actual append commit. For backfilled rows, distinguish that September append from the original source-artifact commit if both are exposed. A smaller fallback is an honestly labelled, unfiltered ledger history link for backfilled rows. Preserve the immutable stored rows. Add a deterministic backfill case and a normal live-publish case that verify the resolved commit/window against known provenance, not just URL syntax.
