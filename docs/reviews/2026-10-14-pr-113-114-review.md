## Findings, highest severity first

### 1. P2 · PR #114 — Preserve missing months for monthly live and hybrid components

**Location:** [pipeline/publish/replay.py:38](https://github.com/ewyluda/macrogauge/blob/c1aa25123dec48fe7a2c7a53b59b5031bc56fa3a/pipeline/publish/replay.py#L38-L39), also [pipeline/publish/gauge_daily.py:19](https://github.com/ewyluda/macrogauge/blob/c1aa25123dec48fe7a2c7a53b59b5031bc56fa3a/pipeline/publish/gauge_daily.py#L19-L21).

The new metadata uses `mode == "live"` to publish an empty missing-month list. That mode identifies the source construction, not the observation cadence or completeness. Regenerating from the reviewed store produces a live `used_vehicles` series with no observations in February, April, June, or September 2026, yet `replay.json` publishes `missing_months: []`. Its latest observation is October 1. The component page consequently displays **6m −8.5%** (`-8.542696363459424%`) using the April 1 grid value, which is actually March's carried level. Supplying April in the metadata makes the actual `annualizedAt` function return `null`, as intended by this PR. The same omission reaches the treemap and the variant chart rates.

The blanket live exemption also affects this PR's specific October-2025 case: a synthetic electricity component built through the real `variants.build_component` year-ratio path retains its missing October-2025 official observation after a live tail is added. Its mode becomes `live`, causing the publisher to discard that historical gap. A current tail must not change whether a historical rate has a valid base.

**Correction:** derive whole-month gaps from the assembled observation dates, distinguishing legitimate cadence where necessary rather than exempting every live component. Preserve gaps in the official portion of hybrid series. Add publisher-to-consumer coverage for a monthly live series and an official-history/live-tail series; assert that the component KPI and relevant chart/treemap values are null at an unavailable endpoint or base.

**Evidence:** saved Python/JavaScript outputs in [the evidence JSON](2026-10-14-pr-113-114-evidence.json), plus [the rendered component page](2026-10-14-pr-114-used-vehicles.png). This reproduction uses the current stored used-vehicle series; the electricity example is explicitly synthetic.

### 2. P2 · PR #114 — Retain the newly generated nulls in the cost-of-living chart

**Location:** [site/src/components/ColChart.tsx:57](https://github.com/ewyluda/macrogauge/blob/c1aa25123dec48fe7a2c7a53b59b5031bc56fa3a/site/src/components/ColChart.tsx#L57-L68), feeding `pair` at line 68; the filtering helper is at lines 17–24.

The new `missingMonths` argument correctly nulls October 2025 and January 2026 in three-month mode, but `ColChart.pair()` drops those points before sending them to ECharts. On the regenerated `/cost-of-living?rate=ann3` page, both lines contain **zero nulls** and no October/January points. The browser therefore draws a straight segment from September 30 to November 1, and from December 31 to February 1. For example, the gauge line connects `−3.3272%` on December 31 to `+2.8694%` on February 1 across the entire undefined January interval. The same problem applies in six-month mode when an endpoint touches October.

The PR already fixes the equivalent helper in `HeroChart`, which is a passing control: it retains all 62 interior null daily points for October/January and draws actual breaks. The cost-of-living helper must use the same behavior. Merely setting `connectNulls: false` cannot fix this once the null points have been removed.

**Correction:** preserve interior null entries in the cost-of-living plot, optionally trimming only leading/trailing nulls as `HeroChart` does. Add a route-level or chart-option assertion using regenerated gap metadata for both annualized modes, checking actual point arrays or rendered discontinuities rather than only the rate-control buttons.

**Evidence:** [rendered chart](2026-10-14-pr-114-col-ann3.png), actual browser option data in [the evidence JSON](2026-10-14-pr-113-114-evidence.json), and the TypeScript helper reproduction below.
